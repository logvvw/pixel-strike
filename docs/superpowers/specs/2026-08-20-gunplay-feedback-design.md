# PixStrike 枪械手感优化设计

日期：2026-08-20

## 目标

在保留现有像素风 Raycasting FPS 架构的前提下，把射击体验提升为“平衡爽快”的 CS 风格：玩家需要控制短点射和压枪，但静止首发更容易命中，命中、爆头与击杀都有清晰且克制的视觉反馈。

本阶段只优化枪械手感，不引入弹丸飞行、穿墙、投掷物、完整团队模式或复杂弹道模拟。

## 成功标准

- 鼠标左键与空格都能射击，半自动武器必须逐次按下，自动武器可按住连射。
- 静止首发精度最高；移动和持续扫射会逐步增大散布。
- 连续射击产生以上抬为主、左右轻微摆动的后坐力，停火后平滑恢复。
- 玩家能通过向下移动鼠标抵消部分后坐力，形成轻量压枪空间。
- 枪口火焰、枪模后坐、屏幕冲击、动态准星、命中标记和击杀条在视觉上保持像素风一致。
- 白色命中、橙红爆头、红色击杀三类反馈可以在瞬间辨认。
- 武器逻辑是确定性、可测试的；随机散布允许注入随机源以稳定测试。
- 现有移动、购买、换弹、波次与胜负循环继续工作。

## 方案选择

采用“反馈状态机”方案：在现有即时命中武器系统上增加射击状态、散布与后坐力模型，并由独立反馈状态驱动 Renderer 与 HUD。该方案不改变 Raycasting 的基本工作方式，性能成本低，也方便逐把武器调参。

不采用以下方案：

- 纯视觉增强：不能形成停步、点射和压枪之间的实际玩法差异。
- 完整弹道模拟：会显著扩大实现范围，且不符合当前小型单机游戏的收益成本比。

## 模块边界

### `js/weapons/weapons.js`

负责武器定义和射击纯逻辑：

- 每把武器新增基础精度、移动散布、每发散布增量、最大散布、散布恢复速度。
- 每把武器新增垂直后坐力、水平后坐力、后坐恢复速度和视觉冲击强度。
- 武器实例记录连续射击次数、当前散布、最后射击时间和后坐状态。
- 射击函数接收玩家运动状态、当前时间和可注入随机源，返回结构化射击结果。
- 射击结果区分未开火、未命中、普通命中、爆头和击杀所需的数据，不直接操作 HUD。

### `js/engine/player.js`

负责玩家运动状态和视角反馈：

- 暴露归一化移动强度，供武器计算移动惩罚。
- 保存武器带来的视觉后坐偏移，并在每帧平滑恢复。
- 后坐力改变镜头方向，但幅度保持可控，玩家向下移动鼠标可以抵消上抬。
- 保留现有碰撞与生命值行为，不把武器配置写入玩家模块。

### `js/engine/feedback.js`

新增纯逻辑反馈状态模块：

- 记录枪口火焰剩余时间、枪模后坐量、屏幕冲击量和命中标记类型。
- 使用基于时间的衰减，不依赖帧数，避免不同刷新率下反馈速度不同。
- 提供 `onShot`、`onHit`、`onKill` 和 `update` 接口。
- 只保存状态，不访问 DOM 或 Canvas，便于单元测试。

### `js/engine/renderer.js`

负责世界内与枪模视觉：

- 在世界渲染完成后绘制低分辨率像素枪模。
- 枪模根据移动速度产生轻微左右摇摆，根据射击状态快速后退并缓慢复位。
- 开火时绘制 40–70 毫秒的块状枪口火焰与短促光晕。
- 命中墙面时可绘制短时像素火花；命中实体仍由 HUD 提供中心反馈。
- 屏幕冲击只使用 1–2 个内部像素的偏移，避免影响瞄准可读性。

### `js/ui/hud.js`

负责屏幕空间反馈：

- 动态准星根据当前散布扩大，停火后平滑收拢。
- 普通命中显示白色四角标记，爆头显示橙红色加粗标记，击杀显示红色强化标记。
- 击杀条在右上角短暂显示武器、敌人和爆头状态。
- 弹匣打空、换弹和低弹药使用文字与颜色提示，不增加遮挡视野的大型弹窗。

### `js/main.js`

只负责串联流程：采集输入、更新武器、调用射击判定、应用伤害、把事件转发给反馈状态与 HUD。具体散布、后坐和动画插值不得继续堆入主循环。

## 射击数据流

1. 输入层检测鼠标左键或空格。半自动武器消费“本帧按下”事件，自动武器读取“持续按住”状态。
2. 主循环把武器、玩家移动强度、当前时间和目标实体交给射击函数。
3. 武器先检查换弹、弹药与射速；无法开火时返回明确原因，不触发射击反馈。
4. 成功开火后增加连续射击次数和当前散布，并从确定性的后坐序列中读取本发上抬与水平摆动。
5. 最终弹道角度由基础准星方向、当前散布采样和可控后坐偏移组成。
6. 即时射线先比较墙体距离与实体距离，只有实体在墙体前方才算命中。
7. 主循环应用伤害并判断普通命中、爆头或击杀，然后分别通知反馈状态和 HUD。
8. 每帧更新散布恢复、后坐恢复和短时特效；Renderer 与 HUD 只读取状态并绘制。

## 手感规则

### 精度与散布

- 静止首发使用每把武器的基础散布。
- 移动惩罚与移动强度成比例，斜向移动不会比直线移动更快或获得额外惩罚。
- 连续开火每发累积散布，达到武器上限后不再增加。
- 停火约 100 毫秒后开始恢复，恢复速度快于累积速度，使短点射节奏清晰。
- 蹲伏与开镜不在本阶段范围内。

### 后坐力

- 前 3–5 发主要垂直上抬，帮助玩家快速理解压枪方向。
- 后续子弹加入较小左右摆动，但不使用完全随机的大幅跳动。
- 后坐序列按射击次数读取；停止射击并恢复后从头开始。
- 镜头后坐与弹道散布分开计算：压枪可以抵消镜头上抬，但不能完全消除连续射击散布。

### 武器定位

- Glock-18：轻后坐、恢复快，适合连续点击。
- MP9：射速快、前几发稳定，持续扫射散布明显。
- AK-47：伤害高，前几发可控，长点射需要压枪。
- AWP：静止时高精度，移动惩罚极高，开火冲击强但不过度晃屏。

## 视觉反馈时序

- 枪口火焰：约 55 毫秒，使用 2–3 帧像素形态切换。
- 枪模后坐：开火瞬间后退，约 100–140 毫秒复位。
- 普通命中标记：约 110 毫秒。
- 爆头标记：约 170 毫秒，并使用橙红色。
- 击杀标记：约 220 毫秒，同时触发右上角击杀条。
- 屏幕冲击：快速进入、平滑退出，位移不超过内部画布 2 像素。

所有时序最终由实际试玩微调，但测试只验证状态转换与边界，不锁死每一个视觉插值帧。

## 异常与边界处理

- 弹匣为空时不触发枪口火焰、后坐、命中标记或击杀反馈。
- 换弹中禁止射击；切换武器时清除上一把枪的短时射击状态。
- 玩家死亡、回合结束或购买菜单打开时停止射击输入并重置反馈。
- 浏览器失去焦点或退出指针锁定后清除持续按键和鼠标按下状态，防止自动射击卡住。
- 无限备弹仍以现有显示规则呈现，不参与数值减法导致 `NaN`。
- 同一敌人的死亡事件只结算一次击杀和分数。

## 测试策略

项目当前没有测试工具链，因此先使用 Node 内置 `node:test`，避免引入构建系统和第三方依赖。

单元测试覆盖：

- 静止、移动和连续射击时散布的变化与上限。
- 停火后的散布与后坐恢复。
- 半自动与自动武器的触发差异。
- 无弹药、换弹中和射速冷却时不会产生射击反馈。
- 注入固定随机源时弹道结果可重复。
- 后坐序列前几发以上抬为主，停止后可以重置。
- 反馈状态的枪口火焰、命中、爆头和击杀时序及优先级。
- 墙体遮挡实体时不产生命中。
- 同一敌人只产生一次击杀事件。

浏览器验收覆盖：

- 鼠标左键和空格均能正常射击。
- 四把武器的后坐、散布和恢复节奏有明显差异。
- 动态准星与实际精度趋势一致。
- 枪口火焰、枪模动画、命中标记和击杀条不会遮挡核心视野。
- 购买、切枪、换弹、死亡与新回合不会遗留错误反馈状态。
- 在常见桌面窗口尺寸下保持清晰的像素缩放和稳定帧率。

## 实施顺序

1. 建立 Node 内置测试入口和纯逻辑测试夹具。
2. 以失败测试定义散布、后坐与反馈状态行为。
3. 实现武器状态与射击结果结构。
4. 接入玩家后坐、输入状态和主循环事件流。
5. 接入 Renderer 枪模与枪口火焰。
6. 接入 HUD 动态准星、命中标记与击杀条。
7. 运行完整自动化测试并进行浏览器试玩验收。

## 非目标

- 不实现真实 CS 武器数据的逐项复刻。
- 不增加联网、队友、炸弹拆装、烟雾弹或穿墙系统。
- 不引入外部图片素材；枪模与反馈优先使用 Canvas 像素绘制。
- 不重写现有地图格式或 Raycasting 世界渲染器。
